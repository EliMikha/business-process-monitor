## Связь с примерами MenuFlow

Изучены примеры из предоставленной лекции
`Week_7_Software_Quality_Engineering_Lecture_RU_MenuFlow_Tests.DOC`:
валидация пустой формы, корректная отправка, скрытие недоступных блюд и
переключение доступности. Использованы те же инструменты: Vitest,
React Testing Library, jest-dom, user-event и jsdom.

Из примеров перенесены принципы: подготовить данные, выполнить пользовательское
действие, проверить наблюдаемый результат; искать поля и действия по роли и
доступному имени; отдельно проверять отсутствие сохранения при ошибке.
Сценарии написаны для процессов собственного MVP. Исходный проект MenuFlow
не запускался: предоставлен документ с примерами.

## Запуск и фактический результат

Из корня репозитория с установленным Node.js 24 LTS:

```sh
npm ci
npm run test:run
```

При блокировке npm.ps1 в PowerShell: `npm.cmd ci` и `npm.cmd run test:run`.
Для режима наблюдения: `npm test`; для выхода: `Ctrl+C`.
Открывать сайт перед запуском тестов не требуется.

Результат запуска 24.10.2026 на Windows и Node.js 24.22.1:

```text
Test Files  3 passed (3)
     Tests  23 passed (23)
```

Использованы Vitest 5.0.5, React Testing Library 16.3.3, jest-dom 7.0.1,
user-event 14.6.8 и jsdom 30.1.3. Точные версии зафиксированы в package-lock.json.

Выполнены первый запуск и повторный запуск после усиления проверок восстановления
этапа и сохранения черновика при отказе записи. Оба запуска успешны.
Ошибок приложения в выбранных сценариях не выявлено; изменять бизнес-логику
для получения успешного результата не потребовалось.

## Организация и границы проверок

- `src/test/validation.test.jsx`: 14 тестов R1.
- `src/test/persistence.test.jsx`: 3 теста R2.
- `src/test/stages.test.jsx`: 6 тестов R3.
- `src/test/setup.js`: DOM-матчеры, очистка интерфейса и хранилища, имитация прокрутки.
- `src/test/helpers.jsx`: запуск настоящего App с MemoryRouter и подготовка сохранённой сессии.

Это интеграционные тесты интерфейса, маршрутов, валидации и хранилища в jsdom.
Валидация, App и функции сохранения не подменяются. Исключение setItem
искусственно воспроизводится только в P02. Перед каждым тестом используется
чистое тестовое хранилище. Повторное монтирование проверяет восстановление из
localStorage, но не является настоящей перезагрузкой браузера.

Внешний вид, физические устройства, реальная прокрутка и сетевое соединение
этими тестами не проверяются. Прокрутка подменена, поскольку jsdom её не реализует.
Тесты не изменяют данные пользователей опубликованного сайта.

GitHub Actions выполняет `npm ci`, `npm run test:run` и сборку до публикации.
При провале тестов последующие шаги публикации не выполняются.

## Использование ИИ

ИИ использовался для анализа требований и лекции, подготовки тестов, настройки
окружения, выполнения запусков и составления описания. Приняты предложения
проверять отсутствие записи при ошибке, границы значений, независимость процессов,
отказ хранилища и отмену всех полей черновика. Результаты в таблице основаны
на фактически выполненном автоматическом запуске. Самостоятельная демонстрация
студентом не выдаётся за проведённую проверку.
