# Business Process Monitor

Учебное приложение для мониторинга трёх заранее заданных бизнес-процессов.
Автор: Михайленко Елизавета Сергеевна, РИМ-160960.

## Открыть сайт в браузере

[Работающий сайт Business Process Monitor](https://elimikha.github.io/business-process-monitor/)

Для проверки по этой ссылке установка программ не требуется. Откройте процесс,
нажмите «Изменить состояние», сохраните изменения и обновите страницу.
Данные сохраняются только в браузере посетителя; у преподавателя будет собственный
набор сохранённых значений.

GitHub Pages автоматически обновляется после отправки изменений в ветку `main`.
Workflow `.github/workflows/deploy-pages.yml` собирает проект с базовым путём
`/business-process-monitor/`. В этой сборке используются маршруты после `#`,
чтобы ссылки на карточку и редактирование открывались и после обновления страницы.
Локальный запуск сохраняет обычные маршруты без `#`.

## Запуск MVP (ЛР №6)

Требуется Node.js 24 LTS и npm. Из корня репозитория:

```sh
npm ci
npm run dev
```

Открыть адрес, показанный в терминале, обычно http://127.0.0.1:5173/.
Приложение React запускается через локальный сервер Vite.

Проверка производственной сборки:

```sh
npm run build
npm run preview
```

## Автоматические тесты (ЛР №7)

Из корня проекта, где находится `package.json`, выполните:

```sh
npm ci
npm run test:run
```

В PowerShell при блокировке `npm.ps1` используйте `npm.cmd ci` и
`npm.cmd run test:run`. Требуется Node.js 24 LTS. Отдельно запускать сайт,
устанавливать браузер или менять данные на опубликованном сайте не требуется.

Ожидаемый итог: `Test Files 3 passed (3)` и `Tests 23 passed (23)`.
Команда завершается после проверки; код завершения `0` означает успех.
Для повторного запуска при изменении файлов: `npm test` (выход: `Ctrl+C`).

| Требование | Что проверяется | Файл |
| --- | --- | --- |
| R1 / FE-016 / F-03 / AC-02 | Неверный ввод не записывается; правила статуса, процента и этапа; допустимые границы | `src/test/validation.test.jsx` |
| R2 / FE-017 / F-05 | Изменения видны в карточке и списке, восстанавливаются; ошибки хранилища обрабатываются | `src/test/persistence.test.jsx` |
| R3 / FE-015 / F-04 / AC-03 | Один следующий этап без изменения процента, ограничения перехода и отмена черновика | `src/test/stages.test.jsx` |

Это интеграционные тесты React-приложения: Vitest, React Testing Library,
user-event, jest-dom и jsdom. Используется настоящий код валидации и сохранения.
Только сценарий отказа хранилища подменяет `setItem`, чтобы воспроизвести ошибку.
Тесты запускаются в изолированной среде и очищают своё хранилище перед каждым
сценарием. jsdom не проверяет внешний вид, реальную прокрутку и адаптивность.

В [описании ЛР №7](docs/lab7-testing.md) приведены ожидаемый результат каждого
теста, результаты запуска и связь с примерами MenuFlow из лекции.
GitHub Actions выполняет тесты перед сборкой и публикацией; при ошибке новая
версия сайта не публикуется. Результат доступен во вкладке **Actions** репозитория.

## Реализованные функции

- Список трёх процессов: название, этап, статус, прогресс, ответственный.
- Карточка процесса с описанием и упорядоченными этапами.
- Изменение статуса и целого процента, переход на один следующий этап.
- Черновик формы, сохранение и отмена. Отмена не записывает изменения.
- Проверка согласованности статуса, процента и текущего этапа.
- Сохранение в localStorage и восстановление после перезагрузки.
- Ошибки ввода и хранилища, сообщение для неизвестного адреса и пустое состояние списка.
- Молочно-коричневое оформление, адаптивность и навигация с клавиатуры.

## Основной сценарий для самостоятельной проверки

1. Открыть «Обработка заказа», затем «Изменить состояние».
2. Ввести 101 и нажать «Сохранить»: должна появиться ошибка, введённое значение остаётся в форме.
3. Исправить процент на 75, нажать «Следующий этап», затем «Сохранить».
4. Убедиться, что отображаются 75% и этап «Передача клиенту».
5. Обновить страницу и проверить сохранённые значения в карточке и списке.
6. Снова открыть редактирование, изменить процент и нажать «Отмена»: сохранённые значения должны остаться прежними.

Сценарий предполагает исходное состояние демонстрационного процесса. При повторной проверке учитывать уже сохранённые значения.

## Правила состояния

| Статус | Процент | Этап |
| --- | --- | --- |
| Не начат | 0 | Первый |
| Выполняется | 1-99 | Любой |
| Завершён | 100 | Последний |
| Заблокирован | 0-99 | Любой |

Переход вперёд доступен только для «Выполняется» до последнего этапа. Процент не меняется автоматически. Все поля формы сохраняются совместно после проверки; ошибка записи сохраняет черновик и не подтверждает успех.

## Структура и ключевые решения

- `src/data/`: фиксированные процессы, сотрудники, этапы и статусы.
- `src/components/`: общие карточки, кнопки, статусы, прогресс и макет страницы.
- `src/pages/`: список, карточка, редактирование и сообщение об отсутствии страницы.
- `src/services/validation.js`: правила проверки состояния.
- `src/services/storage.js`: чтение и запись изменяемых полей в localStorage.
- `src/App.jsx`: маршруты и общее сохранённое состояние React.
- `src/styles/app.css`: обычный CSS, Grid, Flexbox и media queries.
- `public/assets/`: SVG-индикаторы из прототипа; `public/favicon.svg`: иконка BP.
- `tempPage/`: сохранённая HTML/CSS-версия ЛР №4-5.
- `docs/`: требования, прототип, backlog и отчёты.

React хранит актуальное состояние списка. Форма содержит отдельный черновик. При сохранении сначала проверяются параметры и выполняется запись в браузер; только после успешной записи обновляется интерфейс.

## Ограничения

Данные демонстрационные. Создание процессов, изменение структуры этапов, регистрация, backend, база данных, API, совместная работа и синхронизация вкладок не реализуются в первой версии. localStorage действует только в том же браузере и для того же адреса, включая порт. При недоступных или повреждённых данных показаны предупреждение и исходные процессы.

Штатный набор содержит три процесса. Пустой список проверяется на отдельном наборе данных компонента, функции удаления процессов нет. Физические мобильные устройства и настоящий Safari не проверялись. Автоматические тесты ЛР №7 и инструкция их запуска приведены выше.
